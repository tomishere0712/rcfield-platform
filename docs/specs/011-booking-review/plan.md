# Implementation Plan: Booking Review & Rating

**Branch**: `011-booking-review` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/011-booking-review/spec.md`

---

## Summary

Allows customers to rate a completed booking (1–5 stars, 3 optional sub-criteria, free-text note) within 7 days of completion. Ratings are displayed publicly on the cafe detail page. A push notification triggers immediately after session checkout; an in-app reminder banner appears on return visits. Providers can hide violating reviews from their dashboard.

---

## Technical Context

**Language/Version**: Node.js 20+, TypeScript strict mode  
**Primary Dependencies**: Express.js, TypeORM, zod, ws (WebSocket), React 18 + Vite, Tailwind CSS, React Query, Zustand  
**Storage**: PostgreSQL via TypeORM (2 new tables: `reviews`, `review_dismissals`; 1 altered: `bookings`)  
**Testing**: Manual E2E + unit test checklist in quickstart.md  
**Target Platform**: Backend API server + React SPA  
**Project Type**: Web service (multi-tenant SaaS)  
**Performance Goals**: Public cafe review aggregate query < 50ms (PostgreSQL index on `(cafe_id, status)`)  
**Constraints**: Review window = 7 days; 1 review per booking; BYOC bookings suppress vehicle criterion  
**Scale/Scope**: ~50–500 reviews per cafe; aggregate computed on-the-fly

## Key Constraints

- **Notification type**: `BOOKING_REVIEW_REQUEST` — no migration needed (type column is VARCHAR(255))
- **7-day deadline**: Enforced server-side via `bookings.completed_at`; frontend shows inline message "Thời hạn đánh giá đã hết (7 ngày)" + back button when expired (no auto-redirect, no form)
- **BYOC**: `vehicle_score` forced to `null` at service layer regardless of client input
- **No permanent delete**: Provider can only toggle `VISIBLE ↔ HIDDEN`
- **Rating aggregate**: Computed on-the-fly, not cached — reflects hide/unhide immediately on every page load
- **Name masking**: `split(full_name, ' ')` → họ = token[0], remainder = token[1..]; output = `remainder.join(' ') + ' ' + họ[0] + '.'` (e.g. "Văn An N."). Single-token names displayed as-is. Applied in `review.service.ts`.
- **Double-submit**: Frontend disables submit button on first click; DB unique constraint on `booking_id` is passive safeguard
- **STAFF_MANUAL bookings**: Skip `BOOKING_REVIEW_REQUEST` notification; customers can still submit if they navigate directly (service validates ownership + COMPLETED status)
