# Implementation Plan: Provider Onboarding & Subscription Management

**Branch**: `004-provider-subscription` | **Date**: 2026-05-25 | **Spec**: [spec.md](./spec.md)

## Summary

Enable RC field business owners to self-register on RCField, go through an Admin approval flow, and automatically receive a 30-day trial subscription with one branch provisioned. After trial, providers transition through a grace period before branches are soft-deleted. Providers can submit manual bank transfer payment requests; Admin confirms to activate or upgrade subscriptions. All plan limits (branches, AI quota, channels) are enforced at the service layer.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20+  
**Primary Dependencies**: Express.js, TypeORM, PostgreSQL, node-cron, zod  
**Storage**: PostgreSQL (all subscription/payment data)  
**Testing**: Jest (unit tests for state machine + quota enforcement before implementation)  
**Target Platform**: Linux server (same as existing backend)  
**Project Type**: Web service (REST API) + React SPA frontend  
**Performance Goals**: Subscription status check < 100ms p95; quota enforcement < 50ms added latency per webhook call  
**Constraints**: No external payment gateway; no email service in this version (in-app notifications only)  
**Scale/Scope**: ~50–200 provider accounts at launch; daily cron processes all subscriptions in a single pass

## Constitution Check

| Principle | Status | Notes |
|-----------|--------|-------|
| I. Snapshot-First Pricing | ✅ N/A | Feature involves subscription billing, not booking pricing. No `booking.snapshot` interaction. |
| II. State Machine Gate | ✅ APPLIES | `SubscriptionService.transition()` is the sole mutation point for subscription status. Direct DB updates to `provider_subscriptions.status` are forbidden. Same pattern applies to `provider_profiles.registration_status`. |
| III. Evidence-Based Handover | ✅ N/A | No asset handover in this feature. |
| IV. Payment Component Isolation | ✅ N/A | `PaymentRequest` here is a SaaS billing record, distinct from booking `PaymentComponent`. No interaction with the payment component lifecycle. |
| V. Test-First for Financial & State Logic | ✅ APPLIES | Unit tests for `SubscriptionService.transition()` (all valid/invalid pairs) and quota enforcement (branch, AI, channel) must be written before implementation code. |
| VI. RBAC Enforcement | ✅ APPLIES | Provider routes: `authenticate + authorize(PROVIDER)`. Admin routes: `authenticate + authorize(ADMIN)`. Registration endpoint: public (no auth). |

**Scope Exception Justified**: Constitution lists "SaaS tenant/billing" as Phase 2. This spec explicitly promotes it — per the constitution's own rule: *"unless a new spec explicitly promotes them"*. No gate violation.
