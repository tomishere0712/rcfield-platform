# Implementation Plan: Customer Package Purchase & Booking

**Branch**: `003-fb-messenger-channel` (current) | **Date**: 2026-06-11 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/009-customer-package-booking/spec.md`

## Summary

Allow customers to buy slot-based packages per cafe via VNPay, then apply owned packages during booking to waive the slot fee. Packages track `slots_remaining` and `expires_at`; slots are deducted atomically on booking CONFIRMED (pessimistic lock) and refunded on cancellation before `slot_start`. Zero-total bookings (package covers full cost) bypass VNPay entirely.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20+
**Primary Dependencies**: Express.js, TypeORM, PostgreSQL, VNPay (existing gateway), zod, node-cron

**Target Platform**: Linux server (same deployment as existing backend)
**Project Type**: Web service — additional routes and services in existing Express monolith
**Performance Goals**: Slot deduction under 200ms p95 (single FOR UPDATE query)
**Constraints**: Must not break existing booking/payment flows; Constitution Principles I, II, IV, VI apply
**Scale/Scope**: Single B2B provider; expected < 1000 concurrent customers
